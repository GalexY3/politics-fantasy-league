# PFL · ABH30-C05 — La fecha de resolución no es fecha de publicación

**29/10/2026 · Rama `research/pfl-abh30-c05-publication-bitemporal-20261029` · PR sucesora en borrador de #55.**

## Dictamen

Un contraste adversarial de fuentes **ha refutado la interpretación histórica fuerte de C01**. La cohorte pública ForecastBench `2026-09-27-llm.json` se publicó el 27/09/2026 a las 00:08:59Z (Git original `1c1ed16c8d0a1b14e548336b9c4ff91c80809acd`). Sin embargo, el fichero original `2026-09-27_resolution_set.json` **NO aparece en el historial público del mismo repositorio** ni al corte `2026-10-01T23:59:59Z` ni al corte `2026-10-06T23:59:59Z`. El primer commit que modifica/aporta esa ruta consta [el **7 de octubre de 2026 a las 07:19:29Z**](https://github.com/forecastingresearch/forecastbench-datasets/commit/4eafa5cdda4d9fbf3542ea9f5f71050b9dd89110), `4eafa5cdda4d9fbf3542ea9f5f71050b9dd89110`. Su objeto Git de resolución es SHA1 `0b67cfec67fad4b23899e8e48c6ca3a034344edc`, **107.702 bytes re-encodificados y re-hasheados de forma independiente; coincidencia verificada**. El objeto de preguntas sigue siendo `d4c7e1286d76fbaa1c9911ffb0b97cbcc16440c0`.

Anteriormente C01 había aplicado la condición `resolution_date < 2026-10-01` **sobre el fichero descargado en la versión del 29/10** y comunicó que 10 preguntas eran admisibles «al 1 de octubre». Ese cálculo estático es reproducible, pero su interpretación como **información históricamente publicada en esa fuente antes del corte era injustificada**. La fuente original de GitHub no tenía entonces fichero de resoluciones disponible. No se borra C01, no se alteran sus pruebas 15/15 y no se oculta el error: se anota explícitamente la **retractación de aquella inferencia temporal**.

Esto no prueba que las resoluciones fueran desconocidas en todos los mercados ni en otros sitios de Internet: solo habla de la disponibilidad **de ese fichero original en ese repositorio público**. Un commit del archivo completo tampoco establece el `first_public_at` individual de cada fila, y cualquier corrección posterior exige evaluación bitemporal más rigurosa.

## Contrato A–J, evidencia y ejecución

**A. Pregunta:** ¿puede un corte temporal aplicado al campo de fecha de desenlace producir inferencia retrospectiva inválida cuando los datos no se publicaron hasta más tarde?

**B. Hipótesis rivales y falsadores:** (H1) `resolution_date` no garantiza disponibilidad del fichero; el primer snapshot fuente es posterior a Oct01. (H0) existe un commit original de esa ruta antes del 01/10 que refuta el bloqueo. Rival fuerte: la misma información pudo publicarse independientemente antes en las plataformas originales; la prueba no identifica su calendario. Falsadores: aparición de un commit en esa ruta antes de Oct01, que el objeto Git de primera versión no coincida con el SHA fijado, fallos de los 15 tests originales o que una entrada falsa pase por snapshot autorizado.

**C. Diseño y fuente original:** consulta de solo lectura a la API pública oficial de GitHub `commits?path=datasets/resolution_sets/2026-09-27_resolution_set.json&until=<corte>` sobre `forecastingresearch/forecastbench-datasets`, licencia CC BY-SA 4.0 del dataset público. Dos checkpoints congelados de datos originales: `2026-10-08T00:00:00Z` con el primer snapshot del 07/10 y `2026-10-29T16:00:00Z` con `027ba0b3017a60e0e64602d724284ac6b2d91134`, publicado `2026-10-29T07:30:17Z`. **No** se accedió a `forecast_sets`, `user_id`, datos individuales ni tratamientos reales de personas. Recuento de eventos públicos de mercado binarios resueltos condicionado a fecha de fuente y fecha del evento, nunca a una creencia personal.

**D. Freeze previo a ejecutar:** [C05_PREREG_AJ_SOURCE_PUBLICATION.json](C05_PREREG_AJ_SOURCE_PUBLICATION.json), commit `16b505b9ed91c429724f08bfe5fa6761118c80e5`, contrato A–J; [C05_NATIVE_SHA_FREEZE.json](C05_NATIVE_SHA_FREEZE.json), commit `c117b7d0c8d9c1c29aa04aa9c82a7912f1e8781f`. Código Python `src/politics_fantasy/forecastbench_publication.py`, blob Git `91119f6c42f1a4a1ac4126de9ea249d538f862c2`, SHA256 `2dea74904ec9fa00b60e92a5ff542cb1c37b2cbc87316dd7d387bf5b16be89d7`. Tests `tests/test_forecastbench_publication.py`, blob Git `9d1a1afd0a08a4dc010d47f963b9a76ae116dedc`, SHA256 `243b7334d901cd226544b1782f3febfaa497abb0bf1298e1805244a717eb7a41`. **Ambos archivos locales emparejaron exactamente sus blobs en GitHub y sus SHA256 antes del primer test nativo.**

**E. Ejecución efectiva:** **15/15 pruebas Python `unittest` nativas PASS, exit0**. El código rechaza fechas de corte anteriores a 07/10, checkpoints intermedios no verificados, formatos temporales ambiguos, entradas con SHA de fuente falso, sustituciones mediante JSON reserializado y pretensiones de autorizar derechos humanos. Valor conocido `git hash-object` `abc`: `f2ba8f84ab5c1bce84a7b441cb1959cfc7093b7f`, PASS. Después se leyó por conector el **primer fichero de resolución original** `0b67cfec...`, se validó su SHA Git con JS/V8 independiente y se ejecutó el código previamente congelado del guard C01 (blob `0802dd7dd2ead0aa17607f3995aea339efbd9c99`) sobre **las preguntas y resoluciones originales de aquel primer snapshot**. Resultado Oct08: **500 preguntas, 441 registros de resolución y 30 preguntas de mercado binarias admisibles**, con 9 respuestas afirmativas y Brier de predicciones externas observadas `0,1726495082`. La versión posterior original del 29/10 tiene **642 registros de resolución y 52 preguntas admisibles** bajo el corte de ese día. Son **dos versiones de una misma cohorte de fuentes públicas**, no muestras humanas independientes.

**F. Controles y límites:** pruebas negativas de disponibilidad antes del commit, SHA byte idéntico, no sobrelectura de resultados futuros, no validación autoafirmada, y separación `event_time` / `source_commit_time`. La función Python actual solo admite **dos checkpoints fuente exactos**; es intencionadamente conservadora y **no es un cliente universal** que pruebe cualquier fecha o la primera publicación de cada pregunta. **No se ejecutó la función Python recién creada con los dos ficheros reales íntegros en disco**, porque esos bytes no estaban disponibles desde el contenedor local; sus 15 tests nativos sí se ejecutaron y el cálculo positivo de fuente real se hizo con el guard JS existente en el conector. No deben confundirse ambas ejecuciones.

**G. Rival externo:** la metodología de [ForecastBench (Karger et al., ICLR 2025)](https://forecastbench.org/docs/) ya utiliza un benchmark dinámico, correcciones temporales y puntuación Brier ajustada; **no** se reivindica inventar la trazabilidad Git ni la validación temporal. El nuevo punto aquí es una **rectificación de una inferencia propia** a partir de metadatos originales, no una nueva teoría causal.

**H. Priors:** nuevo **PF-BR45** en el libro acumulativo, con referencia exacta a commit original, fecha de primera disponibilidad del fichero, resultado adversarial y límites. Previos PF-BR01–44 conservados. En el ledger C01 se añade `adversarial_source_retraction` sin borrar ni reclasificar sus pruebas originales.

**I. Dictamen:** AB-R **válido de alcance restringido como falsación documental con fuente original** y barrera AB-P probada en casos adversariales, 0/3 ciencia de PFL. No hay efecto causal sobre participación, exposición, opiniones o calidad de pronósticos de usuarios. **CT2 prospectiva científica permanece en 20/100 ordinal**, N1/N2/N3 nuevos **0/0/0**, seis puertas de lanzamiento **0/6**.
